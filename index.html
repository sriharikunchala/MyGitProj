Understanding externalTrafficPolicy: Local

Overview

When using externalTrafficPolicy: Local, the cluster does not forward incoming traffic to other nodes. Traffic is only routed to pods running on the same node that receives the request. This ensures that the client’s IP address is preserved all the way to the pod.

High Availability Recommendation

To maintain high availability, it is recommended to scale the application so that each node has at least one running pod. This allows every node to handle incoming traffic locally.

Best Practice:
  • Match the number of replicas with the number of nodes
  • Ensure even pod distribution across nodes
  • Use proper scheduling strategies if needed

Current Scenario

The cluster consists of 10 nodes, but only 2 pods are running. This means that 8 nodes do not have local endpoints.

Impact:
  • Nodes without local pods cannot serve traffic
  • Incoming requests to those nodes will be dropped
  • This leads to reduced availability and potential service disruption
